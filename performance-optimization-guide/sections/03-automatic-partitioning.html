Automatic Partitioning

Automatic Partitioning analyzes workload and large-table candidates, recommends a partitioning method, and can apply accepted recommendations through the DBMS_AUTO_PARTITION API.

Guide index Series home Series documentation Series glossary Related: new features guide Previous: Automatic Indexing Next: Compression

What it is

Automatic Partitioning analyzes application workload and table metadata to identify large tables that may benefit from partitioning. It uses a single-column partition key with single-level partitioning and can recommend automatic interval, automatic list, or hash partitioning. It does not run as a periodic background task. It runs only when invoked with DBMS_AUTO_PARTITION.RECOMMEND_PARTITION_METHOD.

Partitioning Decision Path
Large Table Object size, statistics, and workload history are reviewed.
Partition Key One useful column is selected from workload predicates.
Method Interval, list, or hash partitioning is recommended.
Pruning Queries scan only relevant partitions when predicates match.
Fewer scanned blocks
Smaller maintenance units
Plan validation with PSTART/PSTOP

Color guide: blue-accent cards highlight candidate inputs or workload signals, gray-accent cards highlight pruning validation, and plain cards show normal partitioning steps.

Method Common fit Performance reason
Automatic interval Date, timestamp, or numeric range data. Range predicates can prune partitions and reduce scan scope.
Automatic list Distinct categories such as region, status, or business unit. Equality predicates can prune partitions by list value.
Hash Large tables without a natural range or list boundary. Rows are distributed across partitions to support parallel access and manageability.

Why it matters

Partitioning can reduce I/O for large-table queries through partition pruning. It also improves manageability because data is organized into smaller physical segments. The benefit depends on workload predicates and table size. A partition key that is rarely used in filters will not provide useful pruning.

Check if enabled

Review configuration, candidate validity, and prior recommendations. Candidate validation is important because Automatic Partitioning has eligibility requirements, including object type, statistics, workload history, and table size.

How to enable

Use REPORT ONLY to generate recommendations without changing tables. Use IMPLEMENT when recommendations should be applied as part of the Automatic Partitioning run. For production environments, run analysis on a clone when possible because recommendation and verification can be resource-intensive.

Test example

This example generates a recommendation for one table, reviews the recommendation, applies it after review, and validates partition metadata. Replace LINEITEM with an eligible large table in your schema. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

VARIABLE recommendation_id VARCHAR2(32)
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET SERVEROUTPUT ON

BEGIN
  :recommendation_id := DBMS_AUTO_PARTITION.RECOMMEND_PARTITION_METHOD(
                          table_owner => USER,
                          table_name  => 'LINEITEM'
                        );
END;
/
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
COLUMN table_name FORMAT A32
COLUMN owner FORMAT A24
COLUMN recommendation_id FORMAT A24
COLUMN partition_key FORMAT A30

SELECT table_owner,
       table_name,
       partition_method,
       partition_key,
       report
FROM   dba_auto_partition_recommendations
WHERE  recommendation_id = :recommendation_id;
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET SERVEROUTPUT ON

BEGIN
  DBMS_AUTO_PARTITION.APPLY_RECOMMENDATION(
    recommendation_id => :recommendation_id,
    table_owner       => USER,
    table_name        => 'LINEITEM'
  );
END;
/
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON

SELECT t.owner,
       t.table_name,
       t.auto,
       t.partitioning_type,
       c.column_name
FROM   dba_part_tables t
JOIN   dba_part_key_columns c
       ON c.owner = t.owner
      AND c.name = t.table_name
WHERE  t.owner = USER
AND    t.table_name = 'LINEITEM';

Expected results

  • Eligible tables should return VALID from VALIDATE_CANDIDATE_TABLE.
  • Recommendations should identify a partition method and partition key only when the workload is expected to benefit.
  • After applying a recommendation, DBA_PART_TABLES should show the table as partitioned and identify the partitioning type.
  • Plans for partition-key predicates should show partition pruning through narrowed PSTART and PSTOP values.
  • If no recommendation is returned, the table may be too small, already manually partitioned, missing required workload history, or not beneficial after verification.
