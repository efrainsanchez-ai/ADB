Automatic Indexing

Automatic Indexing monitors SQL workload, evaluates candidate indexes, validates performance impact, implements useful indexes, and manages automatic index lifecycle.

Guide index Series home Series documentation Series glossary Related: new features guide Previous: Automatic Performance Tuning Next: Automatic Partitioning

What it is

Automatic Indexing automates index management tasks. It observes SQL workload, identifies candidate indexes, validates them, and can create visible automatic indexes when they are expected to improve SQL performance. In Autonomous Database, Automatic Indexing is disabled by default, and Real Application Testing must be enabled before Automatic Indexing can be enabled.

Automatic Indexing Lifecycle
Workload Repeated SQL and predicate patterns are analyzed.
Candidate Potential indexes are created for validation.
Verify Performance benefit and regression risk are checked.
Implement Validated indexes can become visible automatic indexes.
Manage Retention, disablement, and reporting track usefulness.

Color guide: blue-accent cards highlight workload or usage telemetry, gray-accent cards highlight validation gates, and plain cards show normal index lifecycle steps.

Stage Description
Workload analysis The database observes SQL statements and predicate patterns over time.
Candidate creation Potential indexes are created and evaluated by the automatic task.
Validation The database checks whether the candidate improves workload performance without unacceptable regression.
Lifecycle management Automatic indexes can be retained, disabled, or removed based on continued usefulness and configuration.

Why it matters

Index design is workload-dependent. Too few indexes can force expensive scans, while too many indexes increase DML cost and storage usage. Automatic Indexing is useful when access patterns change over time or when teams want the database to test index candidates against observed workload rather than relying only on manual inspection.

Check if enabled

Check the mode first. Then review any automatic indexes and recent reports. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET LONG 100000
SET LONGCHUNKSIZE 100000
COLUMN parameter_name FORMAT A40
COLUMN parameter_value FORMAT A30

SELECT parameter_name, parameter_value
FROM   dba_auto_index_config
WHERE  parameter_name IN (
  'AUTO_INDEX_MODE',
  'AUTO_INDEX_REPORT_RETENTION',
  'AUTO_INDEX_RETENTION_FOR_AUTO',
  'AUTO_INDEX_RETENTION_FOR_MANUAL'
)
ORDER  BY parameter_name;
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
COLUMN status FORMAT A18
COLUMN table_name FORMAT A32
COLUMN owner FORMAT A24

SELECT owner,
       index_name,
       table_name,
       visibility,
       status,
       auto
FROM   dba_indexes
WHERE  auto = 'YES'
ORDER  BY owner, table_name, index_name;

For a table-level review, include index column order. This helps validate whether automatic or manual indexes align with actual predicates. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
COLUMN table_name FORMAT A32
COLUMN owner FORMAT A24

SELECT i.owner,
       i.table_name,
       i.index_name,
       i.visibility,
       c.column_position,
       c.column_name
FROM   dba_indexes i
JOIN   dba_ind_columns c
       ON c.index_owner = i.owner
      AND c.index_name = i.index_name
WHERE  i.auto = 'YES'
AND    i.table_name = 'AI_ORDERS'
ORDER  BY i.owner, i.index_name, c.column_position;

How to enable

Use REPORT ONLY when you want evaluation without implementation. Use IMPLEMENT when you want validated automatic indexes created as visible indexes. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

EXEC DBMS_AUTO_INDEX.CONFIGURE('AUTO_INDEX_MODE', 'REPORT ONLY');
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

EXEC DBMS_AUTO_INDEX.CONFIGURE('AUTO_INDEX_MODE', 'IMPLEMENT');
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

EXEC DBMS_AUTO_INDEX.CONFIGURE('AUTO_INDEX_MODE', 'OFF');
When Automatic Indexing is enabled, index compression for automatic indexes is enabled by default.

Test example

Automatic Indexing depends on observed workload and automatic task execution. This example creates a selective workload and then shows how to review results. A recommendation may not appear immediately. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

CREATE TABLE ai_orders AS
SELECT level AS order_id,
       MOD(level, 10000) AS customer_id,
       DATE '2025-01-01' + MOD(level, 365) AS order_date,
       RPAD('x', 100, 'x') AS padding
FROM   dual
CONNECT BY level <= 500000;
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET SERVEROUTPUT ON

BEGIN
  DBMS_STATS.GATHER_TABLE_STATS(
    ownname          => USER,
    tabname          => 'AI_ORDERS',
    estimate_percent => DBMS_STATS.AUTO_SAMPLE_SIZE,
    method_opt       => 'FOR ALL COLUMNS SIZE AUTO',
    cascade          => TRUE
  );
END;
/
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET SERVEROUTPUT ON

DECLARE
  l_count NUMBER;
BEGIN
  FOR i IN 1..200 LOOP
    EXECUTE IMMEDIATE
      'SELECT COUNT(*) FROM ai_orders WHERE customer_id = :b1'
      INTO l_count
      USING MOD(i, 10000);
  END LOOP;
END;
/
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET LONG 100000
SET LONGCHUNKSIZE 100000

SELECT DBMS_AUTO_INDEX.REPORT_LAST_ACTIVITY(
         type    => 'TEXT',
         section => 'SUMMARY+INDEX_DETAILS+VERIFICATION_DETAILS+ERRORS',
         level   => 'TYPICAL'
       ) AS report
FROM   dual;

Validate whether a new automatic index is used by checking the actual execution plan and comparing logical I/O before and after the index appears. 

SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF

SELECT /*+ gather_plan_statistics */
       COUNT(*) AS order_count
FROM   ai_orders
WHERE  customer_id = 42;
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
SET LONG 100000
SET LONGCHUNKSIZE 100000
COLUMN sql_id FORMAT A15

SELECT *
FROM   TABLE(DBMS_XPLAN.DISPLAY_CURSOR(
         sql_id => NULL,
         cursor_child_no => NULL,
         format => 'TYPICAL +IOSTATS LAST'
       ));
SET LINESIZE 220
SET PAGESIZE 100
SET TRIMSPOOL ON
SET TAB OFF
COLUMN status FORMAT A18
COLUMN table_name FORMAT A32
COLUMN owner FORMAT A24

SELECT owner,
       index_name,
       table_name,
       visibility,
       status,
       auto
FROM   dba_indexes
WHERE  auto = 'YES'
AND    table_name = 'AI_ORDERS';

Expected results

  • REPORT ONLY mode can show recommendations and verification details without creating visible indexes.
  • IMPLEMENT mode can create validated indexes with AUTO = YES.
  • Useful automatic indexes should appear in execution plans as index range scans, index fast full scans, or other index access paths when the optimizer chooses them.
  • If no automatic index appears, the workload may be too small, not selective enough, not repeated enough, or not beneficial after validation.
  • Compare buffer gets and elapsed time per execution instead of assuming that every index improves every query.
